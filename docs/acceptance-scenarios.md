# Sprout acceptance scenarios

Required observable behavior, not completed application tests. Use the [approved testing boundary](specs/sprout-testing-boundary.md), [source corpus](source-validation-corpus.md) and current [open decisions](open-decisions.md).

## Core journey and variants

| Scenario | Required observation |
|---|---|
| Save and retrieve | Save a recipe with intent; inspect originals and supported quantities/steps; find it by name and description |
| Mixed inputs/devices | Capture text, image, video, ticket/document, generic link, Instagram, X, YouTube and WhatsApp-origin material; record actual Galaxy payloads and Windows paste/drop/file behavior |
| Preserve and download | Retained file opens independently of source and while New; downloaded copy opens offline; a URL alone never proves retained video |
| Evidence quality | Footage-only facts use actually analyzed visuals or show the missing modality; one multi-restaurant item exposes each subject without swapping addresses |
| Durable receipt | Interrupt before/after acknowledgement and between attachments, then restart/retry; show one logical receipt or an honest unsaved state with missing parts named |
| Deliberate repeats | Resave with new intent, Space and attachment, then retry that submission; retain the intentional contexts and files without a third receipt or silent summary rewrite |
| Owner correction | Correct summary/fact/category/intent and dispute unsupported claims; retrieval uses corrections, originals survive, and delayed processing cannot overwrite them |
| Review | New remains readable/searchable/downloadable; accept only the previewed understanding; stale preview cannot accept a replacement; correction creates no acceptance chore |
| Tuning control | Change instructions/model settings and preview a sample; output follows requested structure and evidence while existing saved understanding/corrections remain unchanged |
| Spaces | Arrange/group/filter mixed cards, use compact list views and a touch alternative to drag; organization persists after reload and on the other device |
| Shared membership | One item participates in multiple Spaces without divergent originals; membership/Space removal does not silently delete library items |
| Precise recovery | Fail acquisition, initial understanding and indexing separately; recovery repairs only its stage; index repair never invokes enrichment; originals remain accessible |
| Retrieval outcomes | Distinguish no matches, missing answer with matches, supported answer, index pending and AI outage; keep ordinary matches and inspectable supporting evidence |
| Research policy | Inspect outbound requests for Off private material and mixed Off/Fill questions; only permitted minimal context enters lookup; findings retain source/date separately |
| Source authority | Quoted source commands cannot execute actions, modify unrelated items or change approved instructions; core action requests remain Not scheduled |
| Needs your input | Repeated reports deduplicate; repairing one issue leaves unrelated issues and New unchanged; optional answers can stay unknown without blocking use |
| Access and isolation | Reject unauthorized reads/writes/downloads; two users cannot access each other's items, settings, search context, files, exports or processing results |
| Availability/limits | Tunnel expiry or unreachable Windows yields no false save; streamed answers and interrupted/oversized uploads behave honestly; paused AI keeps retained files usable |
| Export and restore | Inspect exported originals, owner context, understanding and organization; separately restore coordinated records/media into a clean location and verify retrieval |
| Trash | Exclude Trash from search/answers immediately; delete during processing, restore within 30 days and interrupt purge; no resurrection, enrichment, action replay or deletion of shared live bytes |

All source-specific limitations and supplied-file workarounds require observed evaluation and the owner's explicit acceptance. Acceptance of a partial pilot does not establish every source/format promised by the core contract.

## Later and advanced checks

- Actions reconcile unknown external outcomes before retries and preserve partial per-operation success; inferred actions require the owner's choice.
- Reminders distinguish scheduling, provider acceptance and actual device delivery; test locked/offline/denied notifications, email failure, downtime, snooze and task completion separately after time policies are settled.
- Linked calendars handle concurrent edits, revoked access, remote deletion and reconnect without stale overwrites, duplicate creation or resurrection; unrelated events remain untouched.
- Rediscovery rechecks Trash, exclusions and feedback before dispatch; no eligible item stays quiet; expired material is not presented as a current opportunity.
- Refinement/history keeps candidate versus current clear, preserves originals through failure/decline/concurrent edits, and never replays actions or silently changes commitments on adoption/restore.
